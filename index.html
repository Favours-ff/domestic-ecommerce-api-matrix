淘宝拉取商品
主列表taobao.items.onsale.get下架补充taobao.items.inventory.get详情补充taobao.item.seller.get
 先分别枚举在售、仓库/下架商品，再按 num_iid 查询详情。 只拉在售接口会漏掉仓库和下架商品；fields 未声明的字段通常不会返回。
淘宝修改SKU库存
主用taobao.skus.quantity.update无SKU商品taobao.item.quantity.update
 skuid_quantities=123:10;456:20；type=1全量，type=2增量。 批量只支持同一商品下SKU，约20条；仓库存模式需改走仓库存接口。
淘宝修改SKU价格
主用taobao.item.sku.price.update一次修改一个SKU。
 num_iid + properties + price，价格单位为元。 主要通过销售属性组合 properties 定位SKU，不应只依赖SKU展示名称。
天猫拉取商品
主列表taobao.items.onsale.get.tmall详情补充taobao.item.get.tmall已知ID批量taobao.items.seller.list.get.tmall
 items.seller.list.get.tmall 按商品ID列表批量查询详情。 天猫存在 .tmall 分流方法；批量详情接口不能替代全店分页枚举。
天猫修改SKU库存
主用tmall.item.quantity.update同一个商品下的SKU批量更新。
 sku_quantities[] 对象数组；options.type 区分全量/增量；增量建议传 outer_biz_key。 无SKU商品与有SKU商品的库存字段不同；增量重试必须防重。
天猫修改SKU价格
主用tmall.item.price.update同一个商品下的SKU批量改价。
 sku_prices[]；可按 sku_id、properties 或 outer_id 定位。 同一次请求不要混合SKU定位方式；活动商品仍可能受营销价格约束。
京东拉取商品
主列表listProductsSKU补充listSkus详情补充getProduct
 scopeSet、page、pageSize；请求头 X-JOS-Request-Identity 区分 vender/supplier。 仅用商品列表可能漏非主商品SKU；POP前10万条、自营前1万条存在深分页范围限制。
京东修改SKU库存
主用batchPutSkuStockPUT sp-product/v0/sku-stocks/batch
 updateModel、stockRfID、putSkuStockList[]；全国仓 warehouseId=0。 warehouseId 与 storeId 只能传一个；官方推荐增量 incrStockIn。
京东修改SKU价格
POP主用jingdong.price.write.updateSkuJdPrice自营商品走供应商价格流程
 skuId + jdPrice，一次一个SKU。 修改基础京东价，不等于促销到手价；自营供应商价格流程不能直接复用POP接口。
拼多多拉取商品
主列表pdd.goods.list.get详情及SKU补充pdd.goods.detail.get
 分页列表取得 goods_id，再补商品详情和SKU详情。 goods_id、sku_id 使用64位整数；不要用Java int。
拼多多修改SKU库存
主用pdd.goods.quantity.update普通SKU库存更新。
 sku_id、quantity、update_type，区分全量和增量。 资源位、秒杀等活动商品可能禁止减库存；日历库存和门票商品需走专用结构。
拼多多修改SKU价格
主用pdd.goods.sku.price.update价格单位为分。
 price、multi_price 等金额字段单位为分。 活动最低价、单买价/团购价关系和商品审核均可能阻止改价。
1688拉取商品
主列表alibaba.product.getList详情补充alibaba.product.get
 列表分页取得商品ID，详情补全SKU、报价模型和库存。 B2B商品可能是SKU定价，也可能是数量区间定价，不能假定统一SKU售价。
1688修改SKU库存
主用alibaba.product.modifyStock库存SKU字段实际传商品 specId。
 productStockChange[]、increaseModify、webSite=1688。 关键特例：skuStocks[].skuId 字段实际传商品详情中的 specId。
1688修改SKU价格
主用alibaba.product.edit前置查询alibaba.product.get先查完整详情，再合并修改价格。
 先读取完整 productInfo，修改 skuInfos[].price 或 priceRanges 后整体提交。 不是轻量单字段改价；必须先识别 quoteType，避免覆盖规格、区间价或起订量。

复杂接口调用流程

仅绘制需要组合调用或存在特殊结构的流程。

淘宝 / 天猫全量商品同步

在售与仓库商品分别枚举，随后补齐详情。

在售列表onsale.get
→
合并商品ID去重 num_iid
→
详情补全seller.get / list.get
同时调用库存/仓库商品列表，否则下架商品会被漏掉。

京东全量商品同步

商品、SKU和详情三类接口承担不同覆盖范围。

listProducts分页商品列表
→
listSkus补非主商品SKU
→
getProduct补完整详情
使用修改时间增量同步；超过深分页上限时按时间窗口拆分。

京东库存更新分支

先确定更新模式，再选择对应数量字段。

生成 stockRfID每个业务动作唯一，防止重复处理
→
全量 fullStockIn传 stockNum
增量 incrStockIn传 incrStockNum，推荐
→
选择库存位置warehouseId 或 storeId 二选一

1688安全改价

必须保留原商品完整结构，避免价格之外的字段被覆盖。

product.get读取完整商品
→
识别 quoteTypeSKU价或区间价
→
product.edit合并原结构提交
不要只提交 productId 和 price；先保留规格、起订量、单位与区间报价。

ERP统一字段建议

统一业务语义，不统一平台请求体。

ERP字段淘宝 / 天猫京东拼多多1688转换规则
product_idnum_iid / item_idproductIdgoods_idproductId统一使用字符串或64位整数存储
platform_sku_idsku_id / propertiesskuIdsku_id保存skuId，同时单独保存specId不要把不同平台SKU标识混为一个字段
seller_skuouter_idouterId（商家SKU编码）outer_id / out_sku_snskuInfo.cargoNumber商家自定义编码；唯一键建议使用“平台+店铺+seller_sku”
price元，小数元，小数分，整数元 / 区间价ERP内部建议统一使用“分”的长整型
stock_update_modetype=1/2fullStockIn/incrStockInupdate_type=1/2increaseModify=false/true库存更新语义：ABSOLUTE目标库存 / INCREMENT增减量
idempotency_key天猫 outer_biz_keystockRfIDERP端维护ERP端维护库存变更防重号，防止超时重试造成重复增减
seller_sku｜商家SKU编码

由商家或ERP维护，用于内部货品映射；它不是平台生成的SKU ID。不同店铺可能重复，因此不建议单字段全局唯一。

stock_update_mode｜库存更新方式

ABSOLUTE表示“库存最终改成20”；INCREMENT表示“在现有库存上增加或减少20”。这是ERP统一字段，不是某个平台的原始字段名。

idempotency_key｜库存变更防重号

同一业务重试时沿用同一个值，防止“库存减1”的请求因超时重发后被执行两次。
